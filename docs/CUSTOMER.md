# Customer

## Job Statement

> When something breaks or I need IT's help, I want to hand my request to someone
> who will own it and show me it's being handled, so I can get back to work and
> not chase it.

Reads without the product name — satisfies the no-solution test. Approved by
user 2026-10-09 (IMPROVE-APP-PLAN Phase 1, decision 1).

## Job Dimensions

| Dimension | The job | Where it underdelivers today | Finding source |
|---|---|---|---|
| Functional | Request lands accurately (right category/priority), progress is visible, nothing slips | Portal submission flow confusing; statuses like *pending* ambiguous; category → priority mapping unclear to end-users | Intake (Phase 1) — "confusing flows / labels" |
| Emotional | Relief: "it's off my plate, IT has it" | Dead-feeling interactions, weak empty-state/error copy → no feedback → user doubts request was seen; no reassurance cues | Intake (Phase 1) — "dead-feeling interactions", "weak copy". **Declared worst dimension (decision 2)** |
| Social | Be seen as a reasonable, legitimate requester — not a chaser | Reference number exists (reassuring) but nothing signals "IT is on it"; status-chasing makes users feel like pests | Intake (Phase 1) |

## Forces of Progress

Which forces push-pull a user from *email/chat/desk* into the portal.

| Force | Evidence |
|---|---|
| Pull | One place, tracked, SLA deadline shown, reference number, status updates |
| Push | Email/chat loses the thread, no ownership, issue blocks work, re-explain daily |
| Anxiety | Will IT actually see it? Is the portal official? Is my request too trivial to bother them? |
| Habit | Email the IT person I know, walk over, call — reset every submission |

Intervention direction (for later phases): reduce **Anxiety** (confirmation,
"seen" state, seen-by-who) and **Habit** (make portal the path of least effort),
not just add Pull.

## Big Hire vs Little Hire

- **Big Hire (adoption):** users trust the portal as the way to reach IT; admins run
  the org on it. Happens once. Internal tool — no acquisition problem.
- **Little Hire (daily loop):** every submission, status check, board view, status
  advance. Complaints concentrate in the agent ticket workflow (create/status/assign)
  → **the leak is Little Hire (decision 3)**. Phases 2-8 target the daily loop.

## Competing Alternatives

| Alternative | Why hired | Weakness |
|---|---|---|
| Email IT person directly | I know them; habit; no portal anxiety | No ownership, lost threads, no SLA, re-explaining |
| Chat (Teams/Slack) | Fast, casual, already open | No tracking, burying, depends on the right person online |
| Walk to IT / call | Immediate, human | High effort, interrupts both sides, no record |
| Don't report (fix myself / live with it) | **Non-consumption** — avoid seeming needy, avoid portal hassle | Critical issues fester unflagged |
| Spreadsheet/manual list (agents) | No cost, no learning | No SLA, no audit, manual staleness |
